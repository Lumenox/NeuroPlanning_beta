BUGS IDENTIFIÉS — App Planning Neurologie
==========================================

1. saveAllPending() et confirmPush() appellent une fonction 
   inexistante `Data()` / `SandboxData()` → ReferenceError capturé 
   silencieusement (catch sans console.error) → toast d'erreur 
   trompeur affiché APRÈS que les écritures aient déjà réussi.
   → Sans conséquence sur les données, mais génère un faux signal 
     d'échec.

2. planning_history n'est alimenté QUE via confirmPlanningSelection 
   (sélection dans le dropdown). Le Mode Pinceau (applyBrushValue) 
   et les éditions d'absences (pendingEditsAbs) n'écrivent JAMAIS 
   dans l'historique, alors que les données sont bien sauvegardées.
   → planning_history n'est pas un journal fiable de toutes les 
     modifications.

3. .update(...).eq('id', rowId) sans .select() : si une policy RLS 
   bloque la ligne (ou si l'id n'existe plus), Supabase renvoie un 
   succès HTTP (204) avec 0 ligne modifiée, sans `error`. Le code 
   actuel ne peut PAS distinguer ce cas d'une vraie sauvegarde.
   → Explication la plus probable de l'incident où A et B pensaient 
     avoir sauvegardé sans que rien ne soit écrit après 15h45, sans 
     aucune erreur visible ni trace exploitable a posteriori.
